# 番茄钟阶段切换需用户确认（自动开始下一阶段设置开关）

## 背景

当前番茄钟在某一阶段倒计时归零后**自动进入下一阶段并立即开始计时**（`timer.rs` 的 `tick()` → `advance_phase(true)`）。用户希望：默认情况下阶段结束后**停在下一阶段等待用户按"开始"**；由用户决定是否开启"自动开始下一阶段"。

## 需求

1. 新增设置项**"自动开始下一阶段"**（开关），**默认关闭**：
   - 关闭（默认）：当前阶段结束后切换到下一阶段，但**暂停**，需用户按"开始"才计时。
   - 开启：保持现有行为，阶段结束后自动开始下一阶段计时。
2. 开关在番茄钟设置弹窗中提供（与时长等配置同一入口），保存后立即生效。
3. 配置持久化到 `pomodoro_config` 表（本地 SQLite，随本机保存）。

## 非目标

- 不改动阶段顺序规则（work → short/long break → work）与长休间隔逻辑。
- 不改动中断（interrupted）处理流程。
- 不参与 WebDAV 同步（`pomodoro_config` 本就不在同步范围内）。
- 不动 `term_phases` 的 PomodoroProfile（那是预设档案，不含运行开关）。

## 行为细节

- 阶段结束切换时：`remaining_seconds` 重置为下一阶段时长；开关关闭时 `is_running = false`，前端展示新阶段但暂停，播放按钮显示"开始"。
- 用户按"开始"后：若为 work 阶段且无活跃 session，正常创建 session（现有 `start_pomodoro` 逻辑已覆盖，无需改动）。
- 开关切换只影响**之后**发生的阶段切换；当前进行中的阶段不受影响。

## 验收标准

- [ ] A1：默认（新装/未改动配置）开关为关闭；专注结束进入短休后**暂停**，按"开始"才计时。
- [ ] A2：开启开关后，专注结束自动进入短休并开始计时（原行为）。
- [ ] A3：短休/长休结束回 work 同样遵循开关（关闭则暂停）。
- [ ] A4：设置弹窗开关保存后重启应用仍生效（持久化）。
- [ ] A5：`cargo test`、`npm run build` 全部通过（含 timer 引擎新增单测）。
